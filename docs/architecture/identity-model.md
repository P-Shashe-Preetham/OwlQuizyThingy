# Architecture Identity Model

## Entities & Identifiers

The system manages identity through several transient and persistent identifiers. There is no traditional user registration or persistent user accounts.

### 1. Manager Identity
*   **Authentication:** Managers are authenticated globally via a single shared password injected via the `MANAGER_PASSWORD` environment variable.
*   **Session State:** Authenticated manager sessions are tracked in memory on the Socket server within a `Set<string>` (the `authenticatedManagers` set) containing the underlying `socket.id`.
*   **Vulnerability/Design Note:** This is a weak identity model. Any disconnect requires immediate tracking cleanup. If the server restarts, all manager sessions are lost. There are no individual manager identities.

### 2. Player Identity
*   **Identifier (`id`):** The transient `socket.id` assigned by Socket.IO upon connection. This is used for routing direct messages to the player.
*   **Client Identifier (`clientId`):** A unique identifier (UUID) generated by the client (web browser) and passed during the initial socket handshake (`socket.handshake.auth.clientId`). This allows a player to reconnect to an ongoing game if their underlying WebSocket connection drops (e.g., due to network instability), as the server can match the reconnecting socket with the established `clientId`.
*   **Username:** A non-unique string provided by the player upon joining (`player:login`). It is only used for display purposes (leaderboard, manager view).
*   **Game State:** The `Player` object holds the current score (`points`), connection status (`connected`), and recent performance metrics (`lastCorrect`, `lastPoints`) within a specific `Game` instance.

### 3. Quiz Identity
*   **Identifier (`id`):** A unique string representing a saved quiz.
    *   If using Firebase Firestore, this is the Firestore Document ID.
    *   If using Local JSON, this is a UUID generated at creation.
*   **Immutability:** When a game is created (`game:create`), the quiz definition is copied by value into the `Game` instance. Subsequent edits to the saved quiz do not affect the running game.

### 4. Game Identity
*   **Identifier (`gameId`):** A unique UUID generated by the server when a game is created. This serves as the internal routing key and the Socket.IO room name.
*   **Invite Code (`inviteCode`):** A human-readable, 6-digit numeric string generated simultaneously with the `gameId`. Players use this to join. The server maintains a mapping to resolve `inviteCode` to `gameId`.
